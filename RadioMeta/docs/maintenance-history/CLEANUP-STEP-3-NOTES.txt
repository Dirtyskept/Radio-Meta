RADIO META v1.3.100 — CLEANUP STEP 3: ORIGINAL METADATA ENGINE
===========================================================

Why this step is conservative
-----------------------------
The metadata reader is central to station detection and song/artist updates. A
source-reference scan did not identify any clearly unreferenced private metadata
methods that are safe to delete. We therefore did not remove parsing, fallback,
ignore-rule, cache, or display-publishing behavior merely because it looks old.

Changes made
------------
1. Fixed the dashboard controller's reported version from the inherited 1.7.0
   label to 1.3.100 in both its readable source section and generated bundle.
   This directly addresses the version-alignment warning in the user's v1.3.99
   diagnostic report.
2. Removed unused C# using directives from the metadata-reader partial files.
   This makes the source less cluttered; it does not by itself reduce DLL size.
3. Removed an IcyReadMetrics object from the one-shot stream test. That path did
   not return or consume the interval count, so the allocation/update was unused.
   The normal playback reader still records interval metrics for diagnostics.
4. Corrected the RadioMetadataReader class comment to describe HTTP/ICY reading
   with FFprobe fallback, which is what the code actually does.
5. Bumped project version to 1.3.100. No plugin GUID or config identity changes.

What was deliberately not changed
---------------------------------
- No stream-title parsing, splitting, ignore phrases, validation, cache policy,
  or metadata publication logic was changed.
- No network endpoint or timeout behavior was changed.
- Proxy code, station file format, station create/edit/delete behavior, library
  refresh behavior, display helper behavior, and WebLoader payload are unchanged.
- No minification was performed.

Important finding for a later performance step
----------------------------------------------
The user's diagnostic report showed repeated Shoutcast endpoint HTTP 404s before
ICY metadata succeeded. The reported recent average was approximately 288 ms for
the Shoutcast attempts and 94 ms for direct ICY reads. This is not a failure when
ICY succeeds, but it is a worthwhile future optimization. It was not changed here
because remembering unsupported endpoints could alter fallback behavior and
needs a separately tested design.

Verification status
-------------------
- The dashboard's source section and generated bundle have matching version data.
- The 15-section dashboard bundle was checked against its recorded source order.
- C# compilation and live Emby playback were not performed in this environment.
  Build on the Windows Emby host before installing.

Recommended user checkpoint
---------------------------
After building, rerun the Radio Meta diagnostic report and confirm the dashboard
bundle version now matches 1.3.100, but a live diagnostic later revealed the assembly reports 1.3.100.0 while the dashboard reports 1.3.100. The follow-up version-alignment fix is documented in CLEANUP-STEP-3-FOLLOWUP-NOTES.txt.
Then verify one ordinary station's song/artist metadata. The full proxy playback
and station-edit smoke tests should still be completed before a release.
