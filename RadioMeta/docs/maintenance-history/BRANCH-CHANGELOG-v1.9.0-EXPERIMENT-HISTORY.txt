RADIO META 1.9.0 — EXPERIMENT BASELINE
=====================================

- Created as a separate experimental line from Radio Meta v1.3.126.
- Preserves the existing metadata/backend services, station management, history,
  proxy, adaptive routing, configuration identity, and diagnostic functionality.
- Advances the project version to 1.9.0; assembly name remains RadioMeta.
- Removes the old WebLoader installer/restore package and the old player-display
  loader/helper resources from the 1.9 project.
- Keeps the Radio Meta settings Dashboard as an embedded Emby plugin page.
- Adds a first experimental DLL-owned player integration path. The DLL embeds
  RadioMetaPlayerIntegration.js, registers it as a plugin resource, and inserts
  one reversible script reference into dashboard-ui/index.html while the plugin
  is active. The DLL removes only its marked reference when its entry point is
  disposed. No external script file is installed.
- The embedded client bridge imports Emby's existing current-player,
  PlaybackManager, and event-bus modules. It updates the current local Audio
  item's in-memory display metadata, raises Emby's native statechange event,
  and intercepts only the matching radio item's `displayitemupdated` event so
  the mini-player and full-player OSD renderers receive the song/artist values
  even when Emby reuses a cached display item for the same .strm ID.
- Dashboard Now Playing cards are updated from the existing session ProviderIds
  (with the Radio Meta CurrentTracks API as a session-ID fallback).
- The first target is song title + artist in the mini-player, full player, and
  Dashboard Now Playing, with station title and .strm artwork excluded.
- This is an experimental client bridge initiated and served by the DLL. It is
  not a purely server-side solution: the DLL adds a marked startup reference to
  Emby's dashboard-ui/index.html so the browser executes the embedded resource.
  It does not modify nowplayingbar.js or any other Emby player source module.

DASHBOARD NOW PLAYING TARGET FIX — REVISION 3
-------------------------------------------
- User diagnostic confirmed that Emby's local PlaybackManager state now contains
  the ICY song title and artist, while the server SessionInfo.NowPlayingItem.Name
  remains the station .strm title. The corresponding RadioMeta ProviderIds are
  present in the session DTO.
- Inspection of the supplied Emby 4.10.2.0 dashboard/dashboard.html confirmed
  that the Active Sessions / Now Playing card list is the .nowPlayingSessions
  element. That template does not contain an element with id dashboardPage.
- The earlier Dashboard updater queried #dashboardPage and therefore returned
  before it could find or update any Now Playing card.
- The updater now targets .nowPlayingSessions directly, uses the actual container
  as its route-presence signal, and exposes dashboardContainerFound and
  dashboardMatchedCards in its diagnostic state.
- This change affects only the DLL-embedded Dashboard display integration; no
  Emby client files, nowplayingbar.js, WebLoader, or userscripts are added.
- Node syntax/smoke tests and live browser verification remain separate checks.


DISPLAY PRESENTATION POLISH — REVISION 4
----------------------------------------
- Following the user's live confirmation that the Emby mini-player, full player,
  and Dashboard Now Playing all update correctly, this revision changes only
  the presentation of the existing song/artist lines. Metadata acquisition,
  session matching, native statechange publishing, and Dashboard track matching
  are not changed.
- Artist text now uses Emby's existing `secondaryText` theme class, so it follows
  the same muted grey/secondary color as other native Emby metadata. This is
  applied to the mini-player, full-player OSD line, and Dashboard card artist.
- The mini-player text rows now use the previous Radio Meta display's block-row
  layout, width/overflow handling, and text-area sizing. The full-player title
  uses the previous two-span song/artist structure with the artist on a
  `secondaryText` line and the original auto-height/overflow treatment. The
  intention is to bring the title stack back toward the prior vertical alignment
  without hard-coded screen coordinates or changes to player geometry.
- The native display elements are restored to their captured original markup
  when Radio Meta metadata stops applying or the active station item changes.
- No Emby source files are patched. All changes are in the DLL-embedded
  RadioMetaPlayerIntegration.js resource. There is no WebLoader, userscript,
  browser extension, or separate client-side file.
- Node.js syntax and the existing native player / Dashboard / bootstrap smoke
  tests pass. Live visual confirmation of the adjusted spacing and color is
  still required on the user's Emby browser.


STATION ARTWORK RESTORATION — REVISION 5
---------------------------------------
- User confirmed that the station logo remains visible on the server-side
  Dashboard Now Playing card but flashes briefly and then disappears from the
  mini-player/full-player in some browser clients, including Safari and remote
  Firefox.
- Source inspection identified the direct cause: the initial text-only test
  deliberately cleared PrimaryImageTag, PrimaryImageItemId, ImageTags,
  PrimaryImageAspectRatio, ImageBlurHashes, and AlbumPrimaryImageTag from the
  browser's local display item. Emby's native now-playing bar reads
  PrimaryImageTag or ImageTags.Primary and uses PrimaryImageItemId/Id for its
  image URL; if those fields are cleared during the Radio Meta state update,
  the image can appear on initial render and then be cleared on the next native
  display-item refresh. The Dashboard continues to show the logo because the
  server-side session DTO is not modified by this local player integration.
- Revision 5 no longer alters any original station image fields or album-art
  fallback fields while applying ICY song/artist text. It preserves the
  original .strm image identity, tag, aspect ratio, blur hash, and image source
  IDs for Emby's own native image resolver. The playback item ID and stream URL
  remain unchanged.
- Added a regression fixture proving that PrimaryImageTag, ImageTags.Primary,
  PrimaryImageItemId, PrimaryImageAspectRatio, ImageBlurHashes.Primary, and
  AlbumPrimaryImageTag survive both the local item update and emitted
  display-item copy.
- Node syntax and simulated player-event/artwork-preservation tests pass.
  Actual logo stability still requires confirmation in the user's browser and
  Safari phone client.


NATIVE DISPLAY FIDELITY — REVISION 6
----------------------------------
- User confirmation: the station logo now remains visible in remote Firefox.
  This revision preserves the current artwork behavior and does not alter any
  original .strm image tags, image IDs, aspect ratio, blur hashes, or album-art
  fallback values.
- Mini-player: removed the earlier custom secondaryText artist styling and left
  the whole now-playing text area to Emby's native nowplayingbar renderer. Its
  song and artist are two equal-style native text rows; Radio Meta no longer
  changes their DOM classes, color, spacing, or vertical position.
- Full player: left Emby's native song-title and artist/subtitle slots untouched.
  The station name is placed only in `.videoOsdThirdTitle`, which is Emby's
  native third/album row. A scoped MutationObserver keeps the station text in
  that slot if the OSD rerenders or restores Album text after a player update.
  The observer does not change the native title or artist row.
- Dashboard Now Playing: song replaces only `.cardText-first`; artist is placed
  in the existing sibling `.cardText-secondary` row. Existing title/artist row
  classes and inline styles are retained. The unused blank runtime row is
  collapsed to prevent it from adding a third line of card height. No nested
  text block, custom font, margin, padding, or vertical offset is introduced.
- This addresses the three surface-specific requirements independently:
  mini-player = song + artist in native equal-style rows; Dashboard = song +
  artist in native title/secondary rows; full player = song + artist + station
  title in the native third/album row.
- Updated the Node smoke test to verify the native slots, no manual mini-player
  styling, preservation of all station artwork fields, and full-player station
  title correction after an OSD re-render.
- Node syntax and smoke tests pass. This is not a C# compilation or a live
  Emby verification; the updated DLL must be built and visually tested on the
  user's Windows Emby instance.


NATIVE SLOT ALIGNMENT AND LEGACY MINI-ARTIST COLOR CLEANUP — REVISION 7

- The change is limited to the DLL-embedded display integration and its smoke

  artwork fields, stream URL, and .strm playback path are unchanged.
- Node syntax and simulated native-slot regression tests pass. C# compilation
